# v0.4.1 标签、进度与打包修复

## 标签上限

NI Digital Pattern Compiler 19.0 对 vector label 的上限是 8191 个。
原实现为每个带标签的 STIL Call 生成标签，大型文件会在第 8192 个标签处失败。

默认自动策略在超限时省略定位标签；始终生成 `pattern_labels.csv`，
保留标签到零基执行周期的映射。显式保留模式超限时，在创建输出目录前报错。
省略标签只适用于当前支持的顺序执行子集；未知跳转语句仍然拒绝。
依赖标签启动的外部流程需要保留相应标签，不能直接改用无标签输出。

## 进度

GUI 和 CLI `--progress` 显示按阶段加权的整体百分比。
Pattern 解析按实际消费的文本位置更新，压缩写入按操作数更新，
展开写入按完成周期数更新。解析避免重复复制剩余正文和从头统计行号。

启用编译时，转换占 0–70%，官方编译、反编译和源文件核对占 70–100%。
NI 工具运行时没有内部百分比，停留在当前阶段并显示工具状态；
进度不是预计剩余时间，校验失败不会显示成功的 100%。

## 本地打包

PyInstaller 显式从当前仓库 `src` 解析模块，避免误用构建环境中旧版 wheel。
`scripts/verify_packaged.py` 检查必需模块，并将安装包中的 Python 字节码
与当前源码在相同优化级别下编译的字节码比较。文件路径不参与比较。
本地和 GitHub Windows 构建均在 GUI 启动自检前执行此检查。

## 验证

- 25 项合成回归通过，包含 8191/8192 边界、自动与显式策略、
  压缩/展开内容保持、百分比单调性及反编译失败不报告成功。
- 官方编译器实际接受 8191 个标签，反编译内容核对通过。
- GUI worker 的压缩与展开文件均完成官方编译和反编译，
  整体进度从 0 到 100；进度条和标签选择在窗口中可见。
- 大型文件全量验证：136,331,583 周期，21,365 个标签自动省略。
  生成、编译、反编译全部成功，源文本及二进制与旧结果仅去标签后的版本逐字节一致。
- 新版 timing 按引脚生成比较时刻：四个纯输入引脚的未使用比较时刻从
  旧版全局 40 ns 改为默认 0 ns；输出引脚的有效比较时刻保持一致。
- Windows 安装包通过源码字节码核对和启动自检。实机加载及硬件运行未验证。
